# Contributing to TiloCompose

Thanks for wanting to contribute! Below are basic steps and rules.

- For major changes open an issue first and propose the approach.
- Create a feature branch from `main` named `feat/short-description`.
- Commit messages: use one of the prefixes `[feat|fix|chore|docs|refactor|test]`.
- Before creating a PR run `./gradlew ktlintFormat` and `./gradlew test` locally.
- In the PR description include: a short summary, how to test the change, screenshots for UI changes, and a list of modified/added tests.

PR checklist:
- [ ] PR description is present
- [ ] Tests added/updated
- [ ] Lint and build pass locally
- [ ] No secrets in commits
- [ ] Assign code reviewer(s)

See `CODING_GUIDELINES.md` for detailed conventions.
